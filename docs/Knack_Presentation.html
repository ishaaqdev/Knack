01 · Introduction

Problem Statement and Objectives

Why technically capable graduates still fail at the parts of the job that decide placement outcomes.

The gap

A graduate who can implement a balanced binary search tree may still be unable to tell a team lead an estimate has slipped, notice that a stated requirement does not match the real need, or catch that generated code calls a library function which does not exist.

These are behavioural skills. They are learned by repeated attempts against realistic situations followed by specific feedback — not by watching lectures and answering multiple-choice questions.

Existing training

  • Content libraries — assess by multiple choice; measure recall of theory, not the ability to communicate.
  • Aptitude platforms — fixed question bank, identical for every candidate, choose from pre-written options.
  • Mock sessions — genuinely effective, but cost scales with headcount and occur 2–4 times a year.

Problem statement

To design and implement a web-based soft-skill training system that generates workplace scenarios personalised to an individual trainee's academic stage, technical background and demonstrated weaknesses; assesses free-text responses with a calibrated rubric; maintains constant inference cost irrespective of accumulated history; and remains usable when the external inference service is unavailable.

Objective 1 — Personalise

Condition every scenario on three independent signals: a stated profile, a distilled public code portfolio, and a context derived from graded attempts.

Objective 2 — Bound the cost

Compress history into a fixed-length summary rewritten at intervals, so prompt size does not grow with the number of attempts completed.

Objective 3 — Assess and adapt

Apply a calibrated 1–10 rubric, scale difficulty from a rolling score and its trend, and degrade gracefully when the model is unreachable.

LLMs as assessors of free text

Automated essay scoring historically used hand-engineered features — length, lexical diversity — which are proxies and trivially gamed [13][14]. Instruction-tuned models can instead apply a natural-language rubric with justification [5][8]. Reported concerns are leniency bias and sensitivity to length independent of quality; our mitigations follow directly from those findings.

Adaptive difficulty and knowledge tracing

Knowledge tracing models a learner's mastery as latent state updated by each observation [15][16][17]. Vygotsky's zone of proximal development [18] motivates targeting tasks just beyond current ability — implemented here as a rolling score with trend-based band shifts.

Memory and context in long-running LLM systems

Three strategies appear in practice. Full-history injection grows without bound and degrades as signal dilutes [25]. Retrieval augmentation [4] bounds cost but retrieves items similar to the query rather than items describing the learner. Recursive summarisation [22][23] holds cost constant and is explicitly about the learner. The third is adopted here.

Gamification and habit

Progress feedback and streaks correlate with sustained engagement [9][12]; leaderboards show short-term gains but can reduce intrinsic motivation among lower-ranked participants [10][11]. Leaderboards were therefore excluded from scope by design.

Why learner_context is 1 : 1, not 1 : N

History is compressed into a single evolving record, not accumulated as rows. That one design decision is what holds prompt size constant however long a trainee trains — and it is the difference between this system and conventional retrieval over past attempts.

Modules and Their Functionality

Ten backend modules and an eight-page client. Prompt templates isolated so they can be tuned without touching route logic.

ModuleRoleFunctionalityKey design decision
auth.jsSecurity scrypt key derivation (N=16384, r=8, p=1, 64-byte key, per-password salt); 32-byte session tokens; route guards. Only the SHA-256 digest of a token is stored — a database dump yields no live sessions.
profile.jsInput Defines the 8 onboarding fields, permitted values, validation, and the phrase each option contributes to the prompt. Served to the client, so validation and UI cannot drift apart.
github.jsInput Reads public repos, excludes forks and archived, discards boilerplate READMEs, distils to technologies and domains. Language and topics lead; READMEs only enrich — most student repos have none worth reading.
context.jsMemory Decides when the learner summary is stale, rebuilds it from a 6-attempt window, supplies the bounded brief. Runs fire-and-forget after the response is sent — never on the request path.
variation.jsGeneration Samples counterpart + power relation, medium, moment and pressure — 18,480 combinations, rotated on coprime strides. Diversity is a property of the sampler, not a hope about the model.
prompts.jsCore Four templates: scenario, evaluation, portfolio distillation, learner summary — including anti-recitation rules. Isolated file so prompts are tunable without touching routes.
ai.jsAdapter OpenRouter client. Cooldown-aware retry, 4-model cross-provider chain, JSON extraction from fenced or prefixed replies. 429 is never retried; reset timestamps are honoured.
gamification.jsRules XP = score × 10 + streak bonus; four levels; calendar-date streaks; rolling 5-score skill with trend; readiness composite. Self-rated confidence seeds starting difficulty only, never the score.
fallback.jsResilience Procedural offline scenarios over the same shape axes, plus a deterministic rubric capped at 7. Output tagged source: offline and labelled in the UI — never passed off as AI.
db.jsStorage SQLite schema in WAL mode, foreign keys enforced, additive migrations. Migrations never discard existing attempts.
React SPAInterface Home · Auth · Onboarding · Track Select · Quest · Feedback · Dashboard · Profile, with route guards. Optimistic XP and streak animation, reconciled against the server.

09 · Challenges, Future Scope and Conclusion

Challenges Faced and Solutions Adopted

Each of these was diagnosed from observed behaviour during implementation, not anticipated in design.

ChallengeDiagnosisSolution adopted
Free-tier quota exhausted in hours OpenRouter allows 50 free requests per day. Our retry policy fired up to 3 attempts across 2 models — 6 requests per scenario, roughly 8 scenarios before the quota died. One attempt per model; 429 never retried; reset timestamps honoured through account-wide and per-model cooldowns, surfaced on /api/health.
The fallback chain was not a fallback Gemma 4 31B and 26B are both served by Google AI Studio, so when that provider throttled, the alternate failed identically. Chain rebuilt across three independent providers — Darkbloom, Nvidia and Google AI Studio.
Scenario mode collapse Nearly every generation read “your team lead wants a shortcut before a deadline”. Instructing the model to vary its output changed wording only. Variation sampled server-side across counterpart, medium, moment and pressure — 18,480 shapes rotated on coprime strides, passed as requirements.
Portfolio anchoring Supplying the free-text GitHub summary caused the model to fixate on one named project; consecutive scenarios were near-duplicates. Split the representation: brief retained for display, prompt receives only bounded technology and domain lists.
Profile recitation Scenarios opened “As a final-year CSE student aiming for a software role…”, placing the trainee outside the situation. Explicit rule that background selects setting and stakes and must never appear in the text.
Reasoning models emitting no JSON Nemotron models write visible chain-of-thought and hit max_tokens before the JSON. Reasoning suppressed in the request; ceiling raised; per-model failure diagnostics logged.
Silent port collision Another local service held 127.0.0.1:5174; our wildcard bind lost to it. The app worked only because localhost resolved to IPv6. Moved to port 5190 and bound loopback explicitly.

Future enhancements

  • Grader validation against human raters — converts the discrimination result into a validity claim. Highest-value next step.
  • Two-grader reconciliation to reduce variance, at roughly double inference cost.
  • Spoken-response track — placement assessment is spoken; add capture and transcription.
  • Instructor view — anonymised class-level weakness aggregation, turning practice data into curricular signal.
  • Achievement badges, skill-tree visualisation, account recovery, native mobile client.

Conclusion

Knack demonstrates that soft-skill training can be made genuinely individual rather than merely automated, and that the individualisation can be sustained at constant inference cost.

The most substantive contribution is the derived context mechanism: by rewriting a bounded summary every three attempts instead of accumulating history, the system carries forward what it has learned about a trainee without cost growth. Its effect is directly observable in feedback that opens “this is the same gap as last time” — a sentence a stateless implementation cannot produce, and the sentence a human mentor would say.

Stated honestly: assessment rests on a single unvalidated grader and evaluation used synthetic profiles, so the demonstrated property is discrimination, not validity.
